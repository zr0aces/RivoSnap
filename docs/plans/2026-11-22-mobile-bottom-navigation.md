# Mobile bottom navigation and More sheet
**Status:** 22 Nov 2026 — Reviewed against the current shell, authentication flow, media viewer and browser tests. Ready for implementation; nothing shipped.

## Goal and scope

Give families one-tap access to their dashboard, photos and albums without scrolling a navigation strip. Keep management tools within two taps. Replace only the authenticated compact navigation at the existing shell breakpoint (820 CSS pixels and below); retain the desktop sidebar from 821px up. Keep the current themes, URL scheme, page layouts and backend. The preview illustrates navigation, not a Gallery redesign.

## Destination map

| Bottom control | Behavior |
| --- | --- |
| Home | Link to the existing Dashboard at `/`; do not rename the page or add a redirect. |
| Gallery | Link to `/gallery`. Filtered Gallery URLs still mark Gallery current. |
| Albums | Link to `/albums`. |
| More | Button opening a bottom sheet, not a fourth route. Highlight it on secondary routes; mark the actual destination link current inside the sheet. |

In order, the sheet contains **Upload queue** (`/jobs`), **LINE groups** (`/groups`), **System health** (`/health`) and **Settings** (`/settings`). Separate **Dark theme** and **Sign out** from the links. Keep the version on Health. Dismissing More must not change the URL, reset filters or lose the current scroll position.

## Task list

- [ ] **Replace only the authenticated compact navigation.** Reuse the destinations, router links, theme state and logout handler in `apps/web/src/main.tsx`. Keep the brand and workspace header; replace the compact horizontal strip and top utilities, not the desktop sidebar. A link to the current path gets `aria-current="page"` even with query parameters. More has a visible secondary-route cue but uses its expanded state to describe the sheet, not `aria-current`. On unknown routes there is no current destination. Leave the shell absent on login, setup, auth loading and auth error; these states must issue no dashboard-stats or health requests.

- [ ] **Define one modal lifecycle.** Keep More state in the compact shell, not in the URL; opening, toggling theme and dismissing must not add history entries. Set `padding: 0` on `<dialog>` and place padding on an inner sheet wrapper so `e.target === dialog` reliably distinguishes a backdrop tap from sheet padding or controls. Reuse the existing theme preference without closing the sheet.
  - Close/Escape/backdrop: return focus to More without moving the underlying page or changing its filters. Selecting a destination, including the current one, closes the sheet and focuses the visible workspace main after navigation; give it a programmatic focus target, not an extra Tab stop.   - Crossing to desktop while open must close the native dialog, release scroll lock and inertness, and focus the matching visible desktop destination (including the Health link), or workspace main if none matches, never a hidden More button. Returning to compact starts closed.
